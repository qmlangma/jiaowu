# 页面模式参考

当需要定义页面级 UI 约束时使用本参考。

## 1. 全局页面规则

- 从用户流程和信息优先级出发，而不是从装饰出发。
- 尽可能让每个页面只有一个主滚动容器。
- 不把横向滚动作为常规阅读方式。
- 同类页面保持稳定的顶层结构。
- Card 只用于重复项、被框定的工具、Modal 和有意义的内容分组。
- 用户要求的是 App / 工具 / 工作台时，不要做成 Landing Page。
- 确保文本和控件在移动端与桌面端都不会溢出或重叠。

## 2. App Shell 模式

适用于 Dashboard、SaaS、后台系统、内部工具和多页面 App。

结构：

- Sidebar 或 Tab navigation：承载一级路由。
- Top bar：承载全局搜索、工作区/账户控制、通知或上下文信息。
- Main content：承载当前路由内容。
- Toast layer：承载瞬时反馈。
- Modal / Sheet layer：承载阻塞流程或上下文流程。

约束：

- 导航宽度、间距和选中状态必须 token 化。
- 主内容默认不包裹装饰性大卡片。
- Shell 背景与路由表面应通过弱层级建立秩序，而不是依赖重阴影。
- 除非流程需要，不要在每个 route 内重复全局控件。

## 3. Dashboard / Workspace 模式

适用于运营首页和日常工作台。

推荐层级：

1. 页面标题与当前上下文。
2. 全局搜索或主要运营控件。
3. KPI 摘要或状态条。
4. 核心工作区域。
5. 次级队列、提醒或快捷入口。

约束：

- 核心工作区域的视觉权重不得低于快捷入口。
- 不超过三层主要视觉层级。
- 状态色只做局部、克制表达。
- KPI 数字使用 tabular digits。
- Alert 面板必须提供清晰处理动作。

## 4. Master-Detail 模式

适用于学员、客户、订单、资产、文件和记录。

结构：

- 左侧列表或表格，支持筛选/搜索。
- 右侧详情面板，使用 Tabs 或分组。
- 明确的选中状态。

约束：

- 切换记录时不应意外重置全局筛选。
- 详情区域在有价值时应保留滚动或分组上下文。
- 空详情态应说明如何选择或创建对象。

## 5. Data Table 模式

结构：

- 筛选/搜索区。
- 表头。
- 对齐一致的数据行。
- 可选批量操作栏。
- 大数据量使用分页或虚拟滚动。

约束：

- 数字保持一致对齐。
- 行内可见操作控制在 2-4 个，其余收进更多菜单。
- 密集运营表格使用固定或稳定列宽。
- 长纵向滚动适合 sticky header。
- Empty、Loading、Error、Filtered Empty 必须区分。

## 6. Form / Modal 模式

结构：

- 标题与简短上下文。
- 分组字段。
- Inline validation。
- Footer 中放主次动作。

约束：

- 必填字段必须清晰。
- 错误出现在字段附近。
- 破坏性或不可逆操作使用清晰文案。
- 提交态必须避免重复提交。
- 长表单使用分组、步骤或草稿保存。

## 7. Detail Page 模式

结构：

- Header：标题、状态和主动作。
- 摘要元信息。
- 主内容分区。
- 相关记录或活动。

约束：

- 状态应靠近标题。
- 主动作应保持易发现。
- 相关字段不要被拆散到距离很远的区域。

## 8. Editor / Canvas 模式

约束：

- 图标需要 Tooltip 或 Label。
- Canvas 是主视觉区域。
- Toolbar 尺寸必须稳定。
- 快捷键只能作为补充，不能替代可见控件。

## 9. Auth 与 Onboarding 模式

约束：

- 主任务必须明确。
- 允许品牌表达，但不得遮挡表单或主动作。
- 认证错误出现在凭证区域附近。
- 工作区切换应显示当前选择，并尽可能即时生效。

## 10. 响应式规则

Web：

- 明确定义断点和布局变化。
- 在文本或控件碰撞前，从多列切换到单列。
- 不使用 viewport 字号缩放。

原生平板：

- 生产力 App 优先适配横屏。
- 竖屏时折叠侧栏，或切换为 split/detail 模式。
- 尊重安全区和系统控件。

移动端：

- 使用 Bottom Sheet 和堆叠布局。
- 主动作保持易触达。
- 避免密集表格，改为分组行或摘要/详情。

桌面端：

- 支持键盘、Hover、Context Menu 和更高信息密度。
- 避免过宽文本行。

## 11. 状态模式

Loading：结构化内容使用 Skeleton；短暂且不可预估的等待可使用 Spinner。

Empty：说明缺少什么，并在适当时提供下一步动作。

Error：说明失败原因和恢复方式，并保留用户输入。

Success：确认已完成的动作；除非需要用户决策，否则不要阻塞用户。

Filtered Empty：说明当前筛选隐藏了结果，并提供重置筛选入口。
