# UI 治理参考

当需要创建评审 checklist、AI 约束或变更控制规则时使用本参考。

## 1. 必须遵循的流程

1. 将需求映射到页面模式。
2. 识别当前事实来源：token、组件库、页面实现、设计文档。
3. 复用既有 token 和组件。
4. 先扩展 token，再添加新的样式值。
5. 新增可复用组件时同步文档化组件契约。
6. 执行与平台匹配的视觉和交互检查。
7. 使用 PR gate 阻止不一致 UI 进入主干。

## 2. AI 开发约束

AI Agent 必须：

- 先检查现有 UI 实现，再生成新的视觉方向。
- 保持产品类型，不把工具/后台 App 做成营销页。
- 对颜色、间距、字体、圆角、描边、阴影、动效和层级使用语义 token。
- 优先使用框架原生组件和平台规范。
- 在创建新的局部样式前复用组件契约。
- 保持主滚动清晰。
- 保留无障碍基线。
- 记录任何有意偏离规范的地方。

AI Agent 不得：

- 在产品页面中新增硬编码颜色。
- 除非整个对象就是状态对象，否则不得用状态色做大面积装饰背景。
- 为了装饰嵌套 card。
- 在已有图标系统之外引入第三方图标风格。
- 只靠颜色表达状态。
- 通过缩小字号掩盖布局问题。
- 在运营类 App 中加入装饰性渐变、光斑、重阴影或玻璃效果，除非现有产品已经采用该风格。

## 3. PR Gate Checklist

Token：

- [ ] 没有新增产品页面硬编码颜色。
- [ ] 正确使用 semantic tokens。
- [ ] 新值添加在正确 token 层级。
- [ ] 字体、间距、圆角、描边、阴影、动效使用 token 或已文档化的局部常量。

Layout：

- [ ] 已识别页面模式。
- [ ] 主滚动行为清晰。
- [ ] 没有常规阅读型横向滚动。
- [ ] 已定义响应式行为。
- [ ] 文本和控件不会重叠或溢出。

Component：

- [ ] 尽可能复用既有组件。
- [ ] 新组件包含用途、结构、变体、状态、token 和无障碍要求。
- [ ] 主动作与次动作层级清晰。
- [ ] 重复卡片、行、表格使用一致尺寸。

Interaction：

- [ ] 点击/触摸目标满足平台最小尺寸。
- [ ] Loading、Empty、Error、Success、Disabled 状态已处理。
- [ ] Focus 状态可见。
- [ ] 破坏性动作有清晰标签和必要保护。

Accessibility：

- [ ] 文本对比度满足 WCAG AA 或平台等价要求。
- [ ] 纯图标控件有 accessible label。
- [ ] 状态不只靠颜色表达。
- [ ] 动效尊重 reduced-motion 设置。

Governance：

- [ ] 文档索引链接到更新后的 UI 规范。
- [ ] 偏离规范的地方写明原因、影响和后续处理。
- [ ] 过期文档已删除或标记为非权威。

## 4. 变更控制

以下变更必须同步更新设计系统：

- 新增颜色角色。
- 新增组件变体。
- 修改间距、圆角或 elevation 约定。
- 修改 Shell / Navigation 结构。
- 引入新页面模式。
- 修改无障碍或交互行为。

新增可复用组件必须先满足组件准入条件，并同步补充组件契约与治理 checklist。

偏离说明格式：

```text
Deviation:
- Rule:
- Reason:
- Scope:
- Risk:
- Owner:
- Review date:
- Planned resolution:
```

## 5. 文档放置建议

推荐文档结构：

```text
docs/ui/
├── README.md
├── UI_FOUNDATIONS.md
├── COMPONENT_LIBRARY_SPEC.md
├── PAGE_PATTERNS_SPEC.md
├── UI_GOVERNANCE.md
└── AI_DEVELOPMENT_DESIGN_CONSTRAINTS.md
```

小项目可合并成一个 `docs/UI_GUIDELINES.md`，但章节必须清晰。

## 6. 过期来源处理

当文档与当前产品冲突时：

1. 判断它是历史记录、未来方向，还是权威规范。
2. 如果是历史记录且不再使用，删除或移入 archive。
3. 如果是未来方向，标注为 future direction。
4. 如果是权威规范但尚未实现，创建后续任务，而不是静默改写规范。
